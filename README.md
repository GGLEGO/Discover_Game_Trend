# Discover Game Trends

스팀 게임 리뷰 블로그 사이트와, 그 사이트에 올릴 글과 댓글을 만드는 에이전트 하네스입니다.

게임명을 하나 넣으면 홈페이지에 게임 블럭이 생기고, 하네스가 리뷰 글 한 편과 그 글에 달릴 댓글 2개를 만들어 블럭의 글 페이지에 올립니다.

## 구성

```
Discover_Game_Trends/
├── server.js              # 사이트 서버 (Node 내장 모듈만 사용)
├── test.json              # 임시 데이터 저장소 (게임, 글, 댓글)
├── logo.png               # 사이트 로고
├── main/                  # 홈페이지
│   ├── index.html         # 게임 블럭 목록과 검색
│   ├── post.html          # 글 페이지와 댓글
│   ├── style.css
│   └── header-bg.svg      # 헤더 배경
├── blog_harness/          # 리뷰 글을 만드는 하네스
│   ├── Operator/Skill.md
│   ├── Researcher/Skill.md
│   ├── Contenter/Skill.md
│   ├── Reviewer/Skill.md
│   └── output/<게임-슬러그>/   # 게임별 작업 기록
└── blog_post_harness/     # 글에 달릴 댓글을 만드는 하네스
    ├── Operator/Skill.md
    ├── Researcher/Skill.md
    ├── Contenter/Skill.md
    ├── Reviewer/Skill.md
    └── output/<게임-슬러그>/
```

## 사이트 실행

Node.js만 있으면 됩니다. 설치할 패키지는 없습니다.

```bash
node server.js
```

브라우저에서 `http://localhost:3000` 을 엽니다. HTML 파일을 직접 열면 데이터를 불러오지 못하므로 반드시 서버를 거쳐 엽니다.

| 환경 변수 | 기본값 | 설명 |
| --- | --- | --- |
| `PORT` | `3000` | 서버 포트 |
| `DATA_FILE` | `./test.json` | 데이터 파일 경로 |

서버는 `0.0.0.0` 에 붙으므로 리눅스 서버에서 그대로 띄울 수 있습니다. `main/` 폴더와 `logo.png` 만 내보내고, `.env` 나 `test.json` 같은 다른 파일은 주소로 열리지 않습니다.

### 화면

- **홈페이지**: 로고와 검색창이 있는 헤더 아래에, `test.json` 에 등록된 게임이 모서리가 둥근 블럭으로 나옵니다. 검색창으로 게임명을 걸러 볼 수 있습니다.
- **글 페이지**: 블럭을 누르면 그 게임의 리뷰 글과 댓글이 나옵니다. 방문자도 댓글을 달 수 있고, 닉네임을 비우면 `Guest` 뒤에 무작위 숫자가 붙습니다.

### API

| 메서드 | 주소 | 설명 |
| --- | --- | --- |
| `GET` | `/api/games` | 게임 목록 (`name`, `hasPost`, `commentCount`) |
| `GET` | `/api/game?name=<게임명>` | 게임 하나의 제목, 본문, 댓글 |
| `POST` | `/api/comments` | 댓글 등록. 본문 `{ game, author, text }`, 닉네임 20자, 내용 500자까지 |

## 데이터 (`test.json`)

지금은 `test.json` 한 파일이 저장소 역할을 합니다. 사이트와 하네스가 모두 이 파일을 읽고 씁니다.

```json
{
  "games": [
    {
      "name": "게임명",
      "title": "글 제목",
      "content": "마크다운 본문",
      "comments": [
        { "author": "Guest4827", "text": "댓글 내용", "date": "2026-11-24T09:30:00.000Z" }
      ]
    }
  ]
}
```

- 게임을 추가하려면 `games` 에 `{ "name": "게임명" }` 을 넣습니다. 홈페이지에 블럭이 바로 생깁니다.
- `title` 과 `content` 가 비어 있으면 글 페이지에 "아직 리뷰 글이 작성되지 않았습니다."가 나옵니다.
- 본문은 마크다운으로 넣습니다. 글 페이지는 제목(`##`), 목록, 굵은 글씨, 인용만 꾸며서 보여 주고 표는 지원하지 않습니다.

## 하네스

두 하네스 모두 네 역할로 이루어져 있습니다. 역할별 지침은 각 폴더의 `Skill.md` 에 있습니다.

| 역할 | 하는 일 |
| --- | --- |
| Operator | 전체 틀을 잡고 브리프를 쓴 뒤 나머지 역할을 순서대로 움직입니다. 결과를 `test.json` 에 올립니다. |
| Researcher | 자료를 조사해 출처와 함께 정리합니다. |
| Contenter | 조사 자료를 바탕으로 글을 쓰고 윤문합니다. |
| Reviewer | 사실, 형식, 문체를 검증해 통과 또는 반려를 판정합니다. |

반려되면 담당 역할이 고친 뒤 다시 검증받습니다. 재작업은 최대 2회입니다.

### blog_harness: 리뷰 글

1. 게임명을 받으면 Operator가 스팀에서 게임을 확인하고 브리프를 씁니다.
2. Researcher가 가격, 플레이 방식, 평가, 사양, 최근 소식을 조사합니다.
3. Contenter가 제목, 목차, 본문(2,000~3,000자)을 쓰고 윤문합니다.
4. Reviewer가 검증합니다. 통과하면 글이 `test.json` 의 `title` 과 `content` 에 들어갑니다.
5. 게임명이 `blog_post_harness` 로 넘어갑니다.

### blog_post_harness: 댓글

완성된 글이 있어야 시작합니다.

1. Researcher가 스팀 사이트의 사용자 평가와 토론 글만 모읍니다. 레딧 같은 다른 커뮤니티는 참고하지 않습니다.
2. Contenter가 글의 내용과 스팀 반응을 참고해 댓글 2개를 새로 씁니다.
   - 하나는 긍정, 하나는 부정입니다.
   - 각 50자 미만입니다.
   - 작성자는 `GuestN` 이고 N은 1000~9999 사이 무작위 숫자입니다.
   - 스팀 댓글을 그대로 가져오지 않습니다. 원문과 어절 3개 이상이 연달아 겹치면 안 됩니다.
3. Reviewer가 글자 수, 근거, 원문과의 겹침을 직접 확인합니다. 통과하면 댓글이 `test.json` 의 `comments` 에 추가됩니다.

### 윤문

두 하네스 모두 글을 쓴 뒤 [im-not-ai](https://github.com/epoko77-ai/im-not-ai)(humanize-korean)로 윤문합니다. 윤문 전 원고는 `draft_raw.md`, 윤문 후 원고는 `draft.md` 로 남고, `draft.md` 끝의 `HUMANIZE-SUMMARY` 블록이 윤문을 거쳤다는 기록입니다. im-not-ai 는 이 저장소에 들어 있지 않으므로 따로 설치해야 합니다.

### 실행 방법

하네스는 Claude Code 같은 에이전트 도구에서 돌립니다. 프로젝트 폴더를 열고 "○○ 게임을 추가해줘"처럼 게임명을 주면, 에이전트가 `blog_harness/Operator/Skill.md` 부터 차례로 따라갑니다. 홈페이지의 블럭이 하네스를 자동으로 실행하지는 않습니다.

### 작업 기록

게임마다 `output/<게임-슬러그>/` 에 아래 파일이 남습니다.

| 파일 | 내용 |
| --- | --- |
| `brief.md` | 브리프 |
| `research.md` | 조사 자료와 출처 |
| `draft_raw.md` | 윤문 전 원고 |
| `draft.md` | 윤문 후 원고 |
| `review.md` | 검증 결과 (회차별) |
| `final.md` | 통과한 최종본 |

## 알아 둘 점

- `test.json` 은 임시 저장소입니다. 여러 사람이 동시에 댓글을 달면 덮어쓸 수 있으므로, 공개하기 전에 데이터베이스로 옮겨야 합니다.
- 댓글에는 글자 수 제한만 있고 도배 방지 장치가 없습니다.
- 하네스가 만든 댓글은 실제 방문자가 쓴 것이 아니라 스팀 반응을 참고해 만든 것입니다. 사이트를 공개할 때는 이 점을 방문자에게 어떻게 알릴지 정해야 합니다.
- 글 안의 가격, 평가 수 같은 수치는 조사한 날 기준입니다.
- `.env` 는 저장소에 올리지 않습니다.
